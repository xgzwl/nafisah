# ADR-002: 聊天 UI 站内原生实现，不采用外部 iframe 挂件

## Status: Accepted (2026-11-26)；v1.1.0 修订 (2026-11-26)，修订依据见 ADR-006

## Background
AI-Chat-Assistant 模板以 DeepAgents + 外部 script + iframe 挂件形式提供，会在 7 页引入不一致的 DOM 与缓存行为，其 `embed.js` 属于 ARCHITECTURE §1.4 的「谨慎（需单独评审，本轮禁止）」类外部脚本。本轮用户已解除「零外链」硬约束（允许 CC BY 署名/来源链接等必要静态外链），但**未要求改变聊天 UI 的实现形态**——原决策的出发点（页面一致性、i18n 全覆盖、无外部脚本注入）依然成立，只是不再以「零外链」作为理由。

## Decision
在 `letters.html` 内用自有 `assets/js/chat.js` 调本站 `POST /chat`；本功能不引入外部 script、iframe、CDN，聊天 UI 保持站内原生。三语文案走现有 i18n 字典。§1.4「允许类」的必要静态外链（如 CC BY 署名链接）与本决策不冲突，不改变聊天实现。`embed.js`/iframe 挂件本轮禁止；若未来确需引入，须先按 §1.4 单独评审（7 页 DOM/缓存一致性、i18n 覆盖、CSP、密钥不落前端），评审通过并更新 ARCHITECTURE 与 UIUX 后方可实施，不擅自改为 iframe。

## Consequences
正面：三语 i18n 可覆盖全部文案、header/footer 不受影响、无外部脚本破坏页面一致性、前端零密钥、EdgeOne 单链路下无需跨平台降级分支。
负面：需自行实现 SSE 读取、`[DONE]` 判定、停止与重试（约 150 行 JS），不享受模板现成 UI。

## Evidence
- `ARCHITECTURE.md` §1.4：必要外链允许三分法（允许 / 谨慎 / 禁止）
- `ARCHITECTURE.md` §6.2：EdgeOne 单链路前端初始化，无 ESA 降级
- `makers-agents/SKILL.md` Critical Rule 7：SSE 协议约定
