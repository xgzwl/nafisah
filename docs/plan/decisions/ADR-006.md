# ADR-006: ESA 下线 + TypeScript 6.0.3 + F3 升 P0 + 必要外链允许（本轮四项裁决）

## Status: Accepted (2026-11-26)

## Background
本轮用户明确四项架构相关调整，原实施计划（ARCHITECTURE v1.0.0 / SPEC / PRD / openapi / ADR-001..005）基于「EdgeOne + ESA 双链路 + ESA 能力探测降级 + 零外链 + TypeScript 5.7.3 + F3 条件纳入」，需整体改口径：
1. 下线 ESA 部署：移除 `esa.jsonc` 与 GitHub 作为部署源的引用；GitHub 可保留为代码备份但不再是部署源。
2. TypeScript 升到 6.x 最新稳定版并同步兼容性配置。
3. F3 从「P1 条件纳入」改为「P0 本轮必交付」，但保留 API Key / CLI 升级 / 安全评审为开工前置条件。
4. 解除「零外链」硬约束，允许必要外链，但不改站内原生聊天 UI、不删 CSP / 密钥不落前端条款。

## Decision

### 1. ESA 下线，EdgeOne 单链路
- 删除 `esa.jsonc`；删除架构文档「双链路」「ESA 能力探测降级」「同源探测四重校验（2xx + content-type + JSON.parse + code===0）」整套方案。
- 明确区分「代码远端」与「部署源」：`github` → `xgzwl/nafisah` 仅作代码备份，**不触发任何部署**；唯一部署源是 CNB `origin` → `xgzwlkj/nafisah`，经 `.cnb.yml` webhook 触发 EdgeOne Makers。
- 前端改为单链路初始化：无 ESA 404Page 误判处理，删 `letters.degraded.*` 降级 i18n key；仅保留一次轻量后端可用性自检（`res.ok && code===0`），失败显示通用错误提示。
- 归档：ADR-004 去除「双链路静态部分一致」措辞；openapi.yaml `info.description` 去除 ESA 降级描述。

### 2. TypeScript 锁 6.0.3 + 兼容配置
- 版本：`typescript@6.0.3`（6.x 线最新稳定版；`npm view typescript versions --json` 显示 6.0.0-beta / 6.0.1-rc / 6.0.2 / 6.0.3；`latest` tag 虽为 7.0.2，但用户明确要 6.x，故锁 6.0.3）。2026-11-26 实测 `npm view typescript@6.0.3 version` → `6.0.3`。
- 新增 `tsconfig.json`（本地 `tsc --noEmit` 专用）：`target: ES2022`、`module: nodenext`（隐含 `moduleResolution: nodenext`）、`strict: true`、`noEmit: true`、`lib: ["ES2022"]`；不设 `types`（默认 `[]`）、不设 `ignoreDeprecations`、不启用 `verbatimModuleSyntax` / `erasableSyntaxOnly`。
- 依据 TS 6.0 官方发布说明：弃用 `moduleResolution: node/node10` 与 `classic`、`target: es5`、`baseUrl`、`alwaysStrict: false`、`downlevelIteration`、`outFile`、`module` 的 amd/umd/systemjs/none、`import asserts` 等；`strict` 默认 true、`module` 默认 esnext、`target` 默认滚动到当年 ES、`types` 默认 `[]`、`rootDir` 默认 `.`。本项目配置未使用任何弃用项，无需 `ignoreDeprecations` 绕过。
- 相对导入扩展名写法以 `edgeone makers dev` 实测为准，标注「待实测」，不臆断。

### 3. F3 升 P0 本轮必交付
- 三功能（F1/F2/F3）同为本轮 P0；原「F3 条件纳入 / 不阻塞前两项 / 可能延后」作废。
- API Key 已创建、CLI 已升 1.7.7、提示词安全评审通过——三项为**开工前置条件（gate）**，不是延期理由；未满足先解除阻塞，不砍 F3。
- 开通在 ARCHITECTURE §0.2 与 §10 步骤 0a 显式列门禁。

### 4. 必要外链允许（撤销零外链硬约束）
- 三分法（与 PRD §0.1「必要外链边界」/ F2-AC5 已对齐）：允许（CC BY 署名/许可凭证链接、素材来源链接、`disclaimer.html` 版权方文字指称、模型网关 `https://ai-gateway.edgeone.link/v1` 服务端调用）；谨慎需评审且**本轮禁止**（外部 script 如 `embed.js`、iframe 挂件、CDN 脚本、第三方字体、统计脚本、插屏广告——聊天保持站内原生，字体全本地）；禁止（前端直连网关、前端持密钥、第三方追踪像素、UGC 信件正文中的外链）。
- ARCHITECTURE 新增 §1.4 定义边界；`AGENTS.md:14/62-64` 与 `README.md` 的「零外链」表述由 team-lead 同步修订（架构师不改这两份文件以免冲突）。
- **保留** CSP 说明条款与「密钥不落前端 / 网关只在服务端调用」安全底线；不删。

## Consequences
正面：部署收敛为单一可验证链路、消除跨平台降级复杂度；版本对齐用户要求且不踩 TS 6.0 弃用项；范围明确无延期歧义；外链边界可执行且不牺牲安全。
负面：ESA 只读镜像不再存在（若曾有 ESA 访客，需自行决定是否公告）；TS 7.0 前须持续跟踪弃用项移除；§1.4「谨慎」类外链（外部脚本/iframe/第三方字体等）本轮禁止，未来若引入需重新评审一致性/CSP，`embed.js` 不得在未评审前上线。

## Evidence
- `npm view typescript versions --json` / `npm view typescript@6.0.3 version`（2026-11-26 实测，team-lead 与本角色各核验一次）
- TypeScript 6.0 官方发布说明：<https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html>（Breaking Changes and Deprecations in TypeScript 6.0 节）
- 官方选参指南：<https://www.typescriptlang.org/docs/handbook/modules/guides/choosing-compiler-options.html>（Node.js 直接运行 → `module: nodenext`）
- 工作区实测：`git remote -v` 显示 `origin`(CNB) / `github` 两个远端；`esa.jsonc` 文件不存在；`edgeone.json` / `.cnb.yml` 存在
